# 投稿の表示位置と本人による編集・削除

## 目的
チャンネルを開くたびに最新投稿までスクロールする手間をなくし、投稿者が自分の投稿を修正・削除できるようにする。既存のCloudflare/D1・単体利用・SSO・参加権限を維持する。

## 提案する動作
- 時系列の並びは維持し、チャンネルを開くと最新投稿が画面内に表示される。DM・返信スレッドも同じ操作感にする。
- 過去を読んでいる最中の他人の投稿や更新では勝手に下へ移動しない。「過去のメッセージ」を読み込むと閲覧位置を維持する。自分の送信後は送信した投稿を表示する。
- 自分のアプリ投稿・返信に「編集」「削除」を表示する。他人の投稿には表示せず、APIでも投稿者本人・現在の参加権限・有効な認証を検査する。
- 編集は本文を対象とし、保存・キャンセル・失敗時の入力保持を備える。「編集済み」を表示する。タグ・依頼先・承認状態などの業務上の属性を本文編集で変更しない。
- 削除は確認を経て行う。本人の本文を非表示にし、他人の返信を巻き込んで削除しない。返信付き親投稿には「削除された投稿」を表示し、返信への入口を保つ。
- 削除済み本文は検索・通知・要対応・添付取得・元メール取得などの読取経路へ残さない。削除済み投稿への編集・リアクション・承認操作も拒否する。
- 受信メールを他の利用者の投稿として編集できるようにはしない。既に送信したメールやCRMへ保存済みの記録は取り消さない（既存の連携方針を維持）。

## 方式
既存メッセージ・ページング・参加権限・リアルタイム更新を利用する。表示順の反転は会話の読み方と過去読み込みを変えてしまうため採用せず、スクロール位置を制御する。投稿の物理削除やスレッド一括削除は返信と参照を壊すため採用せず、削除済み状態を扱う。

## 検証
本人／他人／未ログイン／参加取消／停止ユーザーの編集・削除境界、空本文・競合・編集キャンセル、削除後の返信・検索等の読取経路、チャンネル切替・過去読み込み・閲覧中の更新・送信後のスクロールを検証する。リポジトリ指定の全テスト・型チェック・ビルド・Worker dry-runに加え、PCとスマートフォンの画面を確認する。会社固有設定を維持した固定ソース更新と本番確認まで進める。
